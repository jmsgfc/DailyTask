| 类型 | 天数 | 说明 |

| 功能日 | 65 | 每个 = 1 个可演示的小产出 |

| **合计** | **77** | 每天 40 分钟 |

单日 40 分钟的固定结构：

```
5 min  回看昨天 + 今天要动哪个文件
30 min 实现（不看教程、不重构无关代码）
5 min  跑 test/lint、提交、在本文件打勾
```

## 3. 完成定义（DoD）

一个功能日算完成，需同时满足：

1. 代码已提交，`npm run lint` + `npm run test` 通过；
2. 能在 `npm run tauri dev` 里点出来（UI 类）或用测试跑出来（逻辑类）；
3. 本文件对应行状态改为 `☑`，并写一句实际结果。

里程碑验收以 `docs/impl.md` §8 的验收标准为准，不在这里另立标准。

## 4. 落后处理规则

- **单个任务超时**：40 分钟到点即停，未完成项写进下一复盘日的「遗留」，不自动顺延。
- **连续落后 3 个任务**：砍 M6 的打磨项（纸感细节、动效），保住 M1–M5 可用。
- **连续落后 6 个任务**：把 M4 的「筛选 / 拖拽排序」移出本期，先跑通主链路。
- 周日复盘必须更新本文件的 ☑，否则下一周不算开始。

## 6. 统计口径

- **进度** = 已 `☑` 行数 / 77
- **里程碑进度** = 该里程碑已 `☑` 行数 / 该里程碑功能日数
- 每周日复盘时手写一行：`第 N 周：完成 x/7，里程碑 M? 进度 y/z`
- 本期结束后追加一节「实际耗时与偏差」，记录估算 vs 实际，作为下个周期的校准依据
