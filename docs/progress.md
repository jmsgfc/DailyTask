# DailyTask 开发进度（每天 40 分钟）

> 依据：`docs/impl.md`（架构与里程碑 M1–M6）
> 节奏：每天 40 分钟，周日为复盘日（不排新功能）
> 周期：**2026-11-01 → 2027-01-23**，共 84 天 / 56 小时
> 本文件只负责排期与打卡，架构细节不在此重复

---

## 1. 总量与节奏

| 类型 | 天数 | 说明 |
|---|---|---|
| 功能日 | 67 | 每个 = 1 个可演示的小产出 |
| 复盘日 | 12 | 每周日：跑 lint/test、补漏、更新本文件 |
| 缓冲日 | 5 | M1–M4 各 1 天 + 本期收尾 1 天 |
| **合计** | **84** | 每天 40 分钟，约 56 小时 |

单日 40 分钟的固定结构：

```
5 min  回看昨天 + 今天要动哪个文件
30 min 实现（不看教程、不重构无关代码）
5 min  跑 test/lint、提交、在本文件打勾
```

|---|---|---|---|

缓冲日位于 M1–M4 各里程碑验收之后，以及 01/23 收尾。

## 3. 完成定义（DoD）

一个功能日算完成，需同时满足：

1. 代码已提交，`npm run lint` + `npm run test` 通过；
2. 能在 `npm run tauri dev` 里点出来（UI 类）或用测试跑出来（逻辑类）；
3. 本文件对应行状态改为 `☑`，并写一句实际结果。

里程碑验收以 `docs/impl.md` §8 的验收标准为准，不在这里另立标准。

## 4. 落后处理规则

- **单个任务超时**：40 分钟到点即停，未完成项写进最近的缓冲日，不自动顺延。
- **连续落后 3 个任务**：砍 M6 的打磨项（视觉细节、动效），保住 M1–M5 可用。
- **连续落后 6 个任务**：把 M4 的「筛选 / 拖拽排序」移出本期，先跑通主链路。
- 周日复盘必须更新本文件的 ☑，否则下一周不算开始。
